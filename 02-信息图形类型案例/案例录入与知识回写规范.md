# 案例录入与知识回写规范 V5

**更新：2026-11-23。** 新增课件来源页码、可读节选和案例核验规则。用户补充新图、来源或纠错信息，即触发一次案例与文档的联合更新。

## 唯一的五种基础类型学
编年型、层级型、编目型、字母表型、地理图型，必须按数据和信息的**主导关系**为每张图片选定一个主归属 `primary_logic`；市场表现标签是检索和制作辅助，可有多个，不新增第六类。无法明确归属的案例保持待分类，不纳入正式统计。

## 存储：按表现形式分文件夹，一图一档
每个市场标签拥有独立子文件夹，其下 `00-标签说明.md` 总结同类方法，`案例/CASE-xxxx-作品名/` 中保存图源定位与 `分析.md`，有公开归档许可时可存 `原图.png`（或 jpg/webp）；更多作品依序建立新 CASE 文件夹。单个案例的局部裁切可以作为补充，不可替代原图。

## 五维分析与回写
1. 核验原图、作品名、来源及发布权利，分清事实、图面可见内容与推断；从 PDF 裁出的第三方作品不能直接假定可以公开再发布。
2. 先判定五种基础类型之一，再确定主市场标签以及可选辅助标签。
3. **A** 底层数据关系；**B** 统计图形及计算；**C** 点线面体、图符、色彩、文字编码；**D** 最小字段、Excel 行列、信息组织；**E** 阅读次序、视觉锚点、叙事结构。五项均给出从图中得到的证据。
4. 更新该标签 `00-标签说明.md` 的共性方法与案例链接；把能泛化的规律回写 01 相应理论文档，理论文档**不存图片**，只链接到本 CASE。
5. 更新全库 `案例索引.md`，并验证相对路径、主归属、数据口径和可溯源性。一个 CASE 在多个标签中只保留一份原图，避免重复版本。

## V3 强制新增：基础数据集必须与案例一起入库（2026-11-20）

1. **每案必含 `基础数据集.csv` 和 `数据字典.md`**，同目录放 `分析.md`。图注中的独立数值建议 `辅助指标.csv` 单独建表；数据量太大可扩展多个关联 CSV，不能把多个数据塞入同一单元格。
2. **原子字段、明确粒度**：一行一个最小观测对象；一列一个属性；一个单元格只容纳一个值。数值不混写 `$`、`billion` 等字符串；单位统一为字段约定或独立 `unit` 字段。复合名称（如一个法定都市圈的多地名）作为一个地理实体不属于非法多值。
3. **来源与可靠性**：逐值区分“图面转录”“由现有字段计算”“补充官方数据”和“缺失/无法还原”。保留数据年份、采集时间、统计边界、币种、汇总规则、空值/重复处理。禁止臆造企业源表、经纬度、分类键、投影或作者制作过程。
4. **数据字典**：记录文件、字段名、数据类型、单位、主键/去重规则、最小记录单位、版本、来源 URL 和限制。Excel 最小表要写出行数和列数；常量口径可以写在数据字典中，而非每行冗余。
5. **依次归类、再写回**：`01 唯一五类主归属 → 02 主标签与可选辅助标签 → 拆基础数据集 → A–E 五维拆解 → 具体视觉编码/叙事 → 可操作的重建流程 → 复核 → 回写 01/02/索引`。
6. **版权版图像例外**：原则上同目录保存已获权利允许公开归档的 `原图.jpg/png/webp`；课件图可用“文件名＋PDF 页码＋图面位置”定位，并在 README 记录已核验的版本。有可公开访问的作者或出版方图源时附链接。公开归档状态按实际文件或引用记录。
7. **制作流程**：需明确统计数据处理方法、统计图形、地图/布局准备、尺寸映射方式、引导线规则、阅读顺序、校验清单；不能将“可复刻流程”冒称作者实际制作流程。

## V4｜从图面证据到方法修订

### 1. 逐项记录依据

案例的 A–E 每个维度都要说明“看到了什么、支持什么判断、不能推出什么”。区分以下四种表述：

| 证据类型 | 应记录的依据 | 示例性质 |
|---|---|---|
| 图面观察 | 原图版本、区域、可读标签或可见构图 | 某条曲线连接地图点与外移圆 |
| 数据计算 | 输入字段、公式、单位、舍入或缺失处理 | 对可读营收求和；不从圆径猜数值 |
| 分析推断 | 支持观察、推断理由、其他可能解释 | 高对比圆可能形成阅读入口；没有眼动数据时不称已验证阅读行为 |
| 重建建议 | 为重新制作提出的做法和适用条件 | 建议按面积映射数量；不冒称原作者采用了该公式 |

原图中没有统计图形、体积编码或某种符号时，写明未使用或不适用。文字/列表型的基础数据表可以记录条目、组织键与说明，无需制造数值。

### 2. 对照已有定义，再选择回写动作

| 与已有原则的关系 | 回写动作 |
|---|---|
| 提供新的可复用处理方式 | 增加“方法＋支持 CASE＋适用条件＋限制” |
| 支持已有原则 | 增加证据链接和对应观察，不重复堆积同义段落 |
| 只在特定条件下成立 | 明确范围、数据口径或视觉任务 |
| 构成反例或原分析有误 | 修订或撤回原表述，保留变更原因与反例链接 |
| 仅是个案风格，没有推广依据 | 保留在该 CASE，不硬写成通则 |

“多例支持”须列出全部支持 CASE，不能只凭案例数量宣称普遍有效。未入库的历史讨论可以记录为待核验线索，不计入正式案例或证据数量。

### 3. 同次交付的回写位置

| 文件位置 | 更新内容 |
|---|---|
| 当前 CASE | 原图/来源版本、基础数据、A–E、观察与推断、新发现和缺口 |
| 01 对应主归属定义 | 概括后的逻辑、原则或边界；只用文本链接关联案例 |
| 02 主标签说明 | 本形式的编码、叙事、制作方法和案例链接 |
| 02 辅助标签说明及其案例目录 | 适用于该标签的发现及指向同一 CASE 的链接；不复制原图 |
| 全库案例索引 | 唯一 CASE 记录、基础主归属、主/辅助标签、图像存档状态 |
| [更新记录](../更新记录.md) | 日期、触发、新证据、方法变化与回写位置 |

若已有原则未改变，记录“本例验证已有原则”及证据即可。无法确认的结论留在待核验项，不强行完成概念升级。

### 4. 完成标准

- 同一 CASE 在全库只计一次；主标签案例数、辅助引用数与本地图像数分别统计。
- 五份 01 定义和本轮涉及的 02 类型说明均保留完整 A–E 结构。
- 01 不含图片文件、Markdown 图片、HTML 图片或远程图片嵌入；所有案例入口均为指向 02 的相对文本链接。
- 新增相对链接和标题锚点可解析；图像版本、统计单位及缺失数据表述一致。
- 一次新增案例的分析与知识回写在同次处理中完成。“实时更新”指此流程，并不表示仓库已运行后台监控服务。
